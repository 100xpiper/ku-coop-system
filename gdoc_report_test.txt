บทคัดย่อ
การฝึกปฏิบัติงานสหกิจศึกษาเป็นกระบวนการเรียนรู้เชิงบูรณาการที่สำคัญของนิสิตคณะวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ โดยมีกระบวนการตรวจนิเทศงานของอาจารย์ที่ปรึกษาเป็นหัวใจสำคัญในการติดตามและประเมินผลสัมฤทธิ์ อย่างไรก็ตาม ในระบบการดำเนินงานเดิมพบปัญหาความล่าช้าในการจัดการเอกสารแบบฟอร์มสหกิจศึกษา เอกสารสูญหาย ความคลาดเคลื่อนในการนัดหมายลงพื้นที่ และการขาดหลักฐานเชิงประจักษ์ในการยืนยันว่าอาจารย์ได้ลงพื้นที่ตรวจนิเทศ ณ สถานประกอบการจริงตามเกณฑ์มาตรฐาน
เพื่อแก้ไขปัญหาดังกล่าว โครงงานนี้จึงได้พัฒนาเว็บแอปพลิเคชันแบบตอบสนอง รองรับการใช้งานผ่านคอมพิวเตอร์และสมาร์ทโฟน ครอบคลุมการทำงาน 3 บทบาท ได้แก่ นิสิตสหกิจศึกษา อาจารย์นิเทศ และผู้ดูแลระบบ ระบบได้บูรณาการเทคโนโลยีกล้องสดสแกน QR Code แบบเรียลไทม์ ร่วมกับ Geolocation API และสูตรคำนวณระยะทาง Haversine Formula เพื่อจำกัดรัศมีการเช็คอินนิเทศงานไม่เกิน 500 เมตร ป้องกันการเช็คอินนอกสถานที่จริง พร้อมทั้งพัฒนาระบบคลังภาพถ่ายหลักฐานการนิเทศงานสองชั้น ระบบตรวจรับและข้อคิดเห็นสะท้อนกลับเอกสารรายฉบับ (Granular Review) ระบบนำเข้าข้อมูลนิสิตผ่าน Excel พร้อมตารางพรีวิว และระบบความปลอดภัยยืนยันตัวตนด้วยรหัส OTP 8 หลัก ผ่านอีเมลมหาวิทยาลัยและพร้อมสำหรับการนำไปประยุกต์ใช้งานจริงในระดับคณะต่อไป

Wongsapat Uten 2026: Web Application for Recording and Tracking Cooperative Education Supervision Tasks, Bachelor of Science (Computer Science)
Department of Computational Science and Digital Technology
Project Advisor: Ajarn Prawee Wongsawatsuriya
Abstract
Cooperative education (co-op) is a vital integrated learning process for students in the Faculty of Science at Kasetsart University. A core component of this process is the on-site supervision conducted by faculty advisors, which serves to monitor and evaluate student performance. However, the existing operational system has faced several challenges, including delays in processing co-op documentation, loss of paperwork, scheduling conflicts for site visits, and a lack of empirical evidence to verify that faculty advisors actually visited the workplaces in accordance with established standards.
To address these issues, this project has developed a responsive web application—accessible via both computers and smartphones—that supports three distinct user roles: co-op students, faculty supervisors, and system administrators. The system integrates real-time QR code scanning via the device camera with Geolocation API and the Haversine formula to calculate distance, restricting the check-in radius for site visits to within 500 meters to prevent fraudulent check-ins from off-site locations. Furthermore, the application includes a photo repository for supervision evidence, a granular review system for individual documents, a feature for importing student data via Excel with a preview function, and a security protocol requiring 8-digit OTP verification sent to university email addresses. The system is now ready for implementation at the faculty level.

โครงงานเรื่อง เว็บแอปพลิเคชันการบันทึกและติดตามงานนิเทศสหกิจศึกษา ฉบับนี้ สำเร็จลุล่วงไปได้ด้วยดีเนื่องจากได้รับความกรุณาและการสนับสนุนจากหลายภาคส่วน
ผู้จัดทำขอกราบขอบพระคุณ อาจารย์ปรวี วงศ์สวัสดิ์สุริยะ อาจารย์ที่ปรึกษาโครงงาน เป็นอย่างสูง ที่ได้สละเวลาอันมีค่าในการให้คำปรึกษา ชี้แนะแนวทาง ตลอดจนตรวจสอบและให้ข้อคิดเห็นอันเป็นประโยชน์อย่างยิ่งตลอดระยะเวลาของการดำเนินงาน ซึ่งช่วยให้การพัฒนาระบบและการจัดทำเอกสารมีความถูกต้องตามมาตรฐานทางวิชาการและบรรลุวัตถุประสงค์อย่างสมบูรณ์
ขอขอบพระคุณ คณาจารย์ประจำภาควิชาวิทยาการคอมพิวเตอร์ คณะวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ ทุกท่าน ที่ได้ประสิทธิ์ประสาทวิชาความรู้ด้านวิทยาการคอมพิวเตอร์ วิศวกรรมซอฟต์แวร์ และเทคโนโลยีสารสนเทศ ซึ่งเป็นรากฐานสำคัญในการวิเคราะห์ ออกแบบ และพัฒนาระบบสารสนเทศในครั้งนี้
ขอขอบคุณเจ้าหน้าที่งานสหกิจศึกษา คณะวิทยาศาสตร์ ตลอดจนเพื่อนนิสิตทุกท่าน ที่ได้สละให้ข้อมูลข้อกำหนด และให้ข้อเสนอแนะสะท้อนกลับอันมีค่ายิ่ง ซึ่งช่วยให้ระบบมีความสมบูรณ์ ใช้งานง่าย และตอบโจทย์การปฏิบัติงานจริงได้อย่างมีประสิทธิภาพ
ท้ายที่สุดนี้ ผู้จัดทำขอกราบขอบพระคุณบิดา มารดา และครอบครัว ที่ให้กำลังใจ ให้การสนับสนุนทั้งด้านการศึกษาและความเป็นอยู่เสมอมา ผู้จัดทำหวังเป็นอย่างยิ่งว่าโครงงานฉบับนี้จะเป็นประโยชน์และเป็นแนวทางในการพัฒนาระบบสารสนเทศเพื่อการศึกษาต่อไป

1.1 ที่มาและความสำคัญของปัญหา
หลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาวิทยาการคอมพิวเตอร์ คณะวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ มุ่งเน้นให้นิสิตได้นำองค์ความรู้เชิงทฤษฎีทั้งด้านการพัฒนาซอฟต์แวร์ การจัดการฐานข้อมูล และสถาปัตยกรรมระบบสารสนเทศ ไปประยุกต์ใช้ในการปฏิบัติงานจริง ณ สถานประกอบการผ่านกระบวนการสหกิจศึกษา ซึ่งเป็นกลไกสำคัญในการเตรียมความพร้อมสู่การประกอบอาชีพในอุตสาหกรรมเทคโนโลยีดิจิทัล
ในการดำเนินงานสหกิจศึกษา การออกตรวจนิเทศงานของอาจารย์ที่ปรึกษา ณ สถานประกอบการถือเป็นขั้นตอนสำคัญในการติดตามความก้าวหน้า ให้คำแนะนำด้านวิชาการ และประเมินผลการเรียนรู้ของนิสิตร่วมกับพนักงานพี่เลี้ยง อย่างไรก็ตาม จากการศึกษากระบวนการนิเทศงานเดิม พบปัญหาและข้อจำกัดสำคัญ 4 ด้าน ดังนี้:
1. ปัญหาการจัดการเอกสารและความล่าช้า: การประเมินผลและการส่งเอกสารแบบฟอร์มสหกิจศึกษา ยังคงใช้เอกสารกระดาษหรือไฟล์ที่ส่งผ่านช่องทางไม่เป็นทางการ เช่น อีเมลส่วนตัวหรือแอปพลิเคชันสนทนา ส่งผลให้เอกสารสูญหาย ไม่สามารถตรวจสอบประวัติการส่งได้อย่างเป็นระบบ และอาจารย์นิเทศต้องเสียเวลาในการตรวจรับเอกสารที่ซ้ำซ้อน
2. ความยากลำบากในการติดตามความคืบหน้ารายบุคคลและการแยกหมู่เรียน: แต่ละภาคการศึกษามีนิสิตออกฝึกงานจำนวนมากและแบ่งตามหมู่เรียนจริง ซึ่งระบบเดิมไม่มีการรวมศูนย์ข้อมูล ทำให้อาจารย์และผู้บริหารไม่สามารถมองเห็นภาพรวมสถิติการออกนิเทศแบบเรียลไทม์ได้
3. ปัญหาการนัดหมายลงพื้นที่คลาดเคลื่อน: ขาดระบบปฏิทินกลางที่แสดงผลนัดหมายตรงกันระหว่างอาจารย์ นิสิต และสถานประกอบการ ทำให้ตารางเวลาซ้ำซ้อนหรือไม่ตรงกัน ส่งผลต่อประสิทธิภาพในการวางแผนการเดินทาง
4. การขาดพยานหลักฐานเชิงประจักษ์ในการลงพื้นที่จริง: ขาดเครื่องมือทางเทคโนโลยีที่ช่วยยืนยันและตรวจสอบได้ว่าอาจารย์ได้ลงพื้นที่ตรวจนิเทศ ณ สถานประกอบการจริงตามเกณฑ์มาตรฐานประกันคุณภาพการศึกษาของมหาวิทยาลัย
จากปัญหาดังกล่าว ผู้จัดทำจึงได้พัฒนา เว็บแอปพลิเคชันการบันทึกและติดตามงานนิเทศสหกิจศึกษาขึ้น เพื่อยกระดับการบริหารจัดการการตรวจนิเทศงานสหกิจศึกษาให้มีประสิทธิภาพ รวดเร็ว โปร่งใส และมีหลักฐานเชิงประจักษ์ที่ตรวจสอบได้
1.2 วัตถุประสงค์ของโครงงาน
1. เพื่อศึกษา ออกแบบ และพัฒนาระบบเว็บแอปพลิเคชันบริหารจัดการการตรวจนิเทศงานสหกิจศึกษา คณะวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ ที่รองรับการทำงาน 3 บทบาท (นิสิตสหกิจศึกษา, อาจารย์นิเทศ, ผู้ดูแลระบบ) ในรูปแบบ Responsive Single Page Application
2. เพื่อพัฒนากลไกตรวจสอบและยืนยันการลงพื้นที่นิเทศงานจริง ณ สถานประกอบการ ด้วยการผสานเทคโนโลยี Live Camera Dynamic QR Code Scanner และการตรวจสอบพิกัดภูมิศาสตร์ ร่วมกับสูตร Haversine Formula เพื่อจำกัดรัศมีการเช็คอินไม่เกิน 500 เมตร
3. เพื่อพัฒนาระบบคลังเอกสารแบบฟอร์มสหกิจศึกษา รองรับการอัปโหลดไฟล์ การตรวจรับและส่งคืนข้อคิดเห็นสะท้อนกลับแบบรายฉบับ พร้อมระบบบันทึกและจัดเก็บภาพถ่ายหลักฐานการลงพื้นที่นิเทศงานสองชั้น
4. เพื่อพัฒนาระบบบริหารจัดการข้อมูลนิสิตผ่านการนำเข้าไฟล์ Excel พร้อมตารางพรีวิวและระบบประมวลผลส่งออกรายงานสรุปผลการนิเทศงานในรูปแบบ Excel และ PDF
5. เพื่อประเมินประสิทธิภาพการทำงานและความพึงพอใจของผู้ใช้งานที่มีต่อระบบจัดการการตรวจนิเทศงานสหกิจศึกษาตามมาตรฐาน 
1.3 ขอบเขตของโครงงาน
โครงงานนี้ครอบคลุมการพัฒนาระบบสารสนเทศที่ทำงานในรูปแบบ Web Application โดยแบ่งขอบเขตตามบทบาทผู้ใช้งาน ดังนี้:
1. นิสิตสหกิจศึกษา: สามารถลงทะเบียนเข้าสู่ระบบด้วยอีเมลมหาวิทยาลัย (@ku.th) พร้อมยืนยันตัวตนด้วยรหัส OTP 8 หลัก, แสดงบัตรประจำตัว QR Code, ดาวน์โหลดแบบฟอร์มเปล่า, 
อัปโหลดเอกสารรายงาน, ตรวจสอบผลการอนุมัติและข้อคิดเห็นสะท้อนกลับแบบรายฉบับ, ตรวจสอบปฏิทินนัดหมาย, และตั้งค่าพิกัด GPS สถานประกอบการของตนเอง
2. อาจารย์นิเทศ: สามารถจัดการห้องเรียนแยกหมู่ ตรวจรับและตีกลับเอกสารพร้อมระบุข้อคิดเห็นรายฉบับ, วางแผนนัดหมายลงพื้นที่ผ่านปฏิทินกลาง, เปิดกล้องสดสแกน QR Code เพื่อเช็คอินพิกัด GPS พร้อมระบบตรวจสอบรัศมี 500 เมตร, อัปโหลดภาพถ่ายหลักฐานการนิเทศ, และบันทึกคะแนนประเมินผลตามเกณฑ์รูบริก
3. ผู้ดูแลระบบ: สามารถติดตามแดชบอร์ดสถิตินิเทศงานแบบเรียลไทม์, กรองข้อมูลตามภาคการศึกษาและหมู่เรียน, นำเข้าข้อมูลนิสิตผ่านไฟล์ Excel พร้อมพรีวิวตารางก่อนบันทึก, ระบุพิกัดสถานประกอบการ, และส่งออกรายงานสรุปในรูปแบบ Excel และ PDF

1.4 ประโยชน์ที่คาดว่าจะได้รับ
ผลลัพธ์และสิ่งที่ได้รับจากการดำเนินโครงงานมีความสอดคล้องกับวัตถุประสงค์ของโครงงานในแต่ละข้อ ดังนี้:
1. ได้ระบบเว็บแอปพลิเคชันบริหารจัดการการตรวจนิเทศงานสหกิจศึกษา คณะวิทยาศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ ที่รองรับการทำงาน 3 บทบาท (นิสิตสหกิจศึกษา, อาจารย์นิเทศ, ผู้ดูแลระบบ) มีความเสถียร ปลอดภัย ใช้งานสะดวกทั้งบนคอมพิวเตอร์และสมาร์ทโฟน 
2. ได้กลไกการยืนยันการลงพื้นที่นิเทศงานจริงที่มีความโปร่งใสและสร้างหลักฐานเชิงประจักษ์ สามารถป้องกันการเช็คอินนอกสถานที่จริงได้อย่างแม่นยำด้วยระบบจำกัดรัศมี Geofencing 500 เมตร และการสแกน Dynamic QR Code ผ่านกล้องสด
3. ได้ระบบบริหารจัดการเอกสารแบบฟอร์มสหกิจศึกษาแบบดิจิทัลครบวงจร ช่วยลดการใช้กระดาษ ป้องกันปัญหาเอกสารสูญหาย นิสิตได้รับข้อคิดเห็นสะท้อนกลับรายฉบับเพื่อนำไปปรับปรุงตนเองได้อย่างรวดเร็ว และมีคลังภาพถ่ายหลักฐานการลงพื้นที่ที่ตรวจสอบได้ 
4. ได้เครื่องมืออำนวยความสะดวกแก่ผู้ดูแลระบบในการจัดการข้อมูลนิสิตจำนวนมากผ่านการนำเข้าไฟล์ Excel ได้อย่างถูกต้องแม่นยำด้วยตารางพรีวิว 100% และสามารถประมวลผลส่งออกรายงานสรุปผลการนิเทศในรูปแบบ Excel และ PDF ได้ทันที

2.1 ศึกษาข้อมูลแอปพลิเคชันและระบบที่เกี่ยวข้อง
2.1.1 Google Classroom [1]
Google Classroom เป็นแพลตฟอร์มบนเว็บและโมบายแอปพลิเคชันเพื่อการศึกษาที่ออกแบบมาเพื่ออำนวยความสะดวกในการจัดการห้องเรียนดิจิทัล โดยผู้สอนสามารถรวบรวมและจัดกลุ่มผู้เรียนแยกเป็นห้องเรียนเพื่อความเป็นระเบียบเรียบร้อย ภายในระบบประกอบด้วยพื้นที่รวบรวมไฟล์งานและตรวจส่งเอกสารรายบุคคลของนักเรียนที่ส่งเข้ามา เพื่อช่วยอำนวยความสะดวกในการติดตามความก้าวหน้าและการตรวจเช็คสถานะการส่งงานได้อย่างถูกต้องเป็นระบบ
  

ภาพหน้าหลักของแอปพลิเคชัน
ภาพส่วนของห้องเรียนในclassroom   
จากการศึกษาแอปพลิเคชัน Google Classroom ผู้จัดทำได้นำแนวคิด ระบบบริหารจัดการกลุ่มในลักษณะห้องเรียนจำลองแยกตามหมู่เรียนจริง และ ระบบบริหารจัดการตรวจสอบเอกสารความก้าวหน้ารายบุคคล มาประยุกต์ใช้ในการพัฒนาแอปพลิเคชัน เพื่อให้ระบบนิเทศสหกิจศึกษาสามารถแสดงผลและจัดการกลุ่มนิสิตแยกตามหมู่เรียนในความดูแลของอาจารย์ที่ปรึกษาแต่ละท่านได้อย่างเป็นสัดส่วน พร้อมทั้งอำนวยความสะดวกให้อาจารย์ที่ปรึกษาสามารถตรวจสอบสถานะการส่งแบบฟอร์มเอกสารสหกิจศึกษาและการจัดเก็บไฟล์ภาพถ่ายหลักฐานการลงตรวจนิเทศงานแยกตามรายบุคคลได้อย่างเป็นระบบและมีประสิทธิภาพ
2.1.2 Microsoft Teams [2]
Microsoft Teams เป็นแพลตฟอร์มสำหรับทำงานร่วมกันและสื่อสารกันในองค์กร รวมถึงสถานศึกษา โดยจุดเด่นคือการบูรณาการระบบนัดหมายการทำงานผ่านระบบปฏิทินกลาง (Calendar Calendar) ที่เชื่อมโยงเข้ากับบัญชีผู้ใช้ ทำให้ผู้ใช้งานสามารถจัดตารางเวลานัดหมายการประชุม เลือกช่วงเวลาที่เหมาะสม และระบบจะทำการแสดงผลตารางงานแจ้งเตือนบนหน้าปฏิทินของสมาชิกผู้มีส่วนเกี่ยวข้องโดยอัตโนมัติ ช่วยลดความซ้ำซ้อนของการนัดหมายชนกันและการสับสนด้านวันเวลาในการสื่อสาร

2.2.1 บทความ QR Code Based Smart Attendance System using Mobile Application [3]
บทความ QR Code Based Authentication System using Smart Phone จากวารสารวิชาการด้านวิศวกรรมซอฟต์แวร์ เป็นบทความที่นำเสนอแนวทางการออกแบบส่วนติดต่อผู้ใช้ (User Interface: UI) และระบบสถาปัตยกรรมสำหรับระบบยืนยันตัวตนผ่านอุปกรณ์เคลื่อนที่ โดยมุ่งเน้นการตรวจสอบสิทธิ์การเข้าใช้งานและการระบุอัตลักษณ์ของผู้ใช้งานได้อย่างเหมาะสมโดยไม่สร้างความยุ่งยากจนเกินไป บทความได้เริ่มต้นด้วยการอธิบายองค์ประกอบของการเข้ารหัสสองมิติตอบสนองรวดเร็วแต่ละประเภท เช่น Static QR Code, Dynamic QR Code, Barcode และ RFID ซึ่งแต่ละประเภทมีลักษณะการใช้งานและจุดประสงค์ที่แตกต่างกัน ตัวอย่างเช่น RFID ใช้สำหรับการสแกนผ่านบัตร ณ จุดทางเข้าหลัก ในขณะที่ Static QR Code เหมาะสำหรับการขอการยืนยันตัวตนหรือข้อมูลประจำตัวจากผู้ใช้เมื่อต้องการแลกเปลี่ยนข้อมูลผ่านหน้าจอมือถือโดยตรง
นอกจากนี้ บทความยังได้แนะนำแนวทางการออกแบบ UI สำหรับการสแกนรหัสที่ควรคำนึงถึง เช่น การเลือกใช้โทนสีและการจัดวางกรอบสำหรับจับภาพ QR Code ที่มีความหมายชัดเจนและเข้าใจง่าย การกำหนดขนาดและการประมวลผลความสว่างหน้าจอที่เหมาะสม การเปิดโอกาสให้ผู้ใช้สามารถตรวจสอบความถูกต้องของรหัสประจำตัวได้เองตามความต้องการ รวมถึงการใช้แอนิเมชันหรือสัญลักษณ์เมื่อสแกนผ่านเพื่อช่วยเพิ่มความน่าสนใจและทำให้ขั้นตอนการยืนยันตัวตนดูไม่แข็งทื่อ
ตัวอย่างการใช้งานจริงที่ยกมา เช่น การสแกนรหัสเพื่อจับคู่ข้อมูลประจำตัวระหว่างผู้ตรวจสอบและผู้ใช้งาน หรือการเข้าถึงแบบฟอร์มบันทึกผลโดยอัตโนมัติหลังจากการถอดรหัสข้อมูลเสร็จสิ้น ซึ่งเป็นตัวอย่างที่สะท้อนให้เห็นว่าการออกแบบที่ดีช่วยเสริมประสบการณ์ผู้ใช้ (User Experience: UX) ได้เป็นอย่างมาก โดยทำให้ผู้ใช้ได้รับข้อมูลที่จำเป็นทันเวลา และไม่รู้สึกว่าการยืนยันตัวตนด้วยรหัสผ่านกล้องถ่ายภาพเป็นสิ่งรบกวน

2.2.2 บทความ Location-Based Student Attendance Tracking System Using GPS Technology [4]
บทความ Location-Based Verification System using Smart Phone จากวารสารวิชาการด้านเทคโนโลยีสารสนเทศ เป็นบทความที่นำเสนอแนวทางการออกแบบส่วนติดต่อผู้ใช้ (User Interface: UI) และระบบสถาปัตยกรรมสำหรับระบบตรวจสอบพิกัดสถานที่ปฏิบัติงานของผู้ใช้งาน โดยมุ่งเน้นการตรวจสอบพื้นที่ผ่านการระบุตำแหน่งดาวเทียมที่สามารถระบุความถูกต้องของตำแหน่งได้อย่างเหมาะสมโดยไม่สร้างความคลาดเคลื่อนจนเกินไป บทความได้เริ่มต้นด้วยการอธิบายองค์ประกอบของการระบุตำแหน่งภายนอกอาคารแต่ละประเภท เช่น Global Positioning System (GPS), Assisted GPS (A-GPS), GLONASS และ Cellular Network ซึ่งแต่ละประเภทมีลักษณะการใช้งานและจุดประสงค์ที่แตกต่างกัน ตัวอย่างเช่น Cellular Network ใช้สำหรับการระบุพื้นที่กว้าง ๆ ในขณะที่ GPS หรือ A-GPS เหมาะสำหรับการขอการยืนยันตัวตนหรือข้อมูลพิกัดละติจูดและลองจิจูดจากผู้ใช้เมื่อเข้าปฏิบัติงานอยู่ภายในรัศมีของสถานที่เป้าหมาย
นอกจากนี้ บทความยังได้แนะนำแนวทางการออกแบบ UI สำหรับการดึงข้อมูลพิกัดที่ควรคำนึงถึง เช่น การแสดงสถานะการเปิดรับสัญญาณดาวเทียมที่เข้าใจง่าย การเปิดและปิดระบบเรียกพิกัดเฉพาะจังหวะที่ทำรายการเพื่อการประหยัดพลังงาน การเปิดโอกาสให้ผู้ใช้สามารถตรวจสอบตำแหน่งที่ถูกบันทึกผ่านระบบแผนที่ออนไลน์ได้เองตามความต้องการ รวมถึงการใช้หน้าต่างสรุปผลข้อมูลพิกัดเพื่อช่วยเพิ่มความน่าสนใจและทำให้การจัดเก็บพิกัดดูไม่แข็งทื่อ
ตัวอย่างการใช้งานจริงที่ยกมา เช่น การบันทึกพิกัดสถานที่โดยอัตโนมัติพร้อมเวลา (Timestamp) ในขณะที่เกิดกิจกรรมการสแกนตรวจสอบ หรือการแสดงหมุดตำแหน่งการเช็กอินบนระบบแผนที่ดิจิทัล ซึ่งเป็นตัวอย่างที่สะท้อนให้เห็นว่าการออกแบบที่ดีช่วยเสริมประสบการณ์ผู้ใช้ (User Experience: UX) ได้เป็นอย่างมาก โดยทำให้ผู้ใช้ได้รับข้อมูลที่จำเป็นทันเวลา และไม่รู้สึกว่าการตรวจสอบพื้นที่ปฏิบัติงานด้วยสัญญาณดาวเทียมเป็นสิ่งรบกวน

2.2.3 บทความ Development of Mobile Information System for Cooperative Education Supervision [5]
บทความ Classroom-Style Group Management and Scheduling System using Smart Phone จากวารสารวิชาการด้านเทคโนโลยีการศึกษา เป็นบทความที่นำเสนอแนวทางการออกแบบส่วนติดต่อผู้ใช้ (User Interface: UI) และระบบสถาปัตยกรรมสำหรับระบบจัดการกลุ่มและการนัดหมายทำกิจกรรม โดยมุ่งเน้นการจัดระเบียบข้อมูลผู้ใช้งานและการสื่อสารร่วมกันเป็นกลุ่มได้อย่างเหมาะสมโดยไม่สร้างความซับซ้อนจนเกินไป บทความได้เริ่มต้นด้วยการอธิบายองค์ประกอบของการบริหารจัดการกลุ่มประสานงานแต่ละประเภท เช่น หน้ากระดานข่าวสารรวม (Stream/Feed), ระบบรหัสเข้ากลุ่ม (Class Code), ปฏิทินนัดหมายแบบจำลอง (In-App Calendar) และระบบแจ้งเตือน ซึ่งแต่ละประเภทมีลักษณะการใช้งานและจุดประสงค์ที่แตกต่างกัน ตัวอย่างเช่น รหัสเข้ากลุ่มใช้เพื่อความสะดวกรวดเร็วในการลงทะเบียนสมาชิก ในขณะที่หน้ากระดานข่าวสารและปฏิทินนัดหมายเหมาะสำหรับการแจ้งข้อมูลสำคัญหรือตารางเวลาการทำกิจกรรมร่วมกันเพื่อให้ผู้ใช้งานในกลุ่มได้รับทราบอย่างพร้อมเพรียงกัน
นอกจากนี้ บทความยังได้แนะนำแนวทางการออกแบบ UI สำหรับการจัดการกลุ่มและปฏิทินที่ควรคำนึงถึง เช่น การเลือกใช้ไอคอนและโทนสีของปฏิทินแยกตามสถานะนัดหมายที่ชัดเจนและเข้าใจง่าย การจัดสรรพื้นที่หน้า Feed ให้สามารถอ่านข้อความประกาศได้อย่างสะดวก การเปิดโอกาสให้ผู้ใช้สามารถตรวจสอบวันเวลาการนัดหมายย้อนหลังได้เองตามความต้องการ รวมถึงการใช้ระบบจุดแจ้งเตือนสีแดง (In-App Notification) เพื่อช่วยเพิ่มความน่าสนใจและทำให้การติดตามตารางงานดูไม่แข็งทื่อ
ตัวอย่างการใช้งานจริงที่ยกมา เช่น การอัปเดตสถานะปฏิทินอัตโนมัติเมื่อผู้สอนหรือผู้บันทึกทำการจองวันเวลานัดหมาย หรือการแจ้งเตือนความจำบนแถบกระดิ่งเมื่อมีการอัปเดตกิจกรรมใหม่ภายในกลุ่ม ซึ่งเป็นตัวอย่างที่สะท้อนให้เห็นว่าการออกแบบที่ดีช่วยเสริมประสบการณ์ผู้ใช้ (User Experience: UX) ได้เป็นอย่างมาก โดยทำให้ผู้ใช้ได้รับข้อมูลที่จำเป็นทันเวลา และไม่รู้สึกว่าการจัดการตารางนัดหมายและการติดต่อสื่อสารเป็นกลุ่มเป็นสิ่งรบกวน

2.3 เครื่องมือที่ใช้ในการพัฒนาระบบ
2.3.1 HTML (HyperText Markup Language) [9]
HTML คือภาษาคอมพิวเตอร์มาตรฐานที่ใช้สร้างและกำหนดโครงสร้างของหน้าเว็บ (Web Structure) โดยใช้การเขียนแท็ก (Tags) เพื่อรับรองและควบคุมการแสดงผลของข้อความ รูปภาพ ฟอร์มกรอกข้อมูล และส่วนประกอบต่าง ๆ บนหน้าจออย่างเป็นระเบียบ ในโครงงานนี้ HTML ถูกใช้เป็นโครงสร้างหลักในการสร้างหน้าต่างและส่วนติดต่อผู้ใช้ (User Interface) ของแอปพลิเคชันทั้งหมด ทั้งหน้าต่างแดชบอร์ด คลังแบบฟอร์มเปล่า และหน้าต่างตรวจรับเอกสาร
2.3.2 CSS (Cascading Style Sheets) [10]
CSS คือภาษาที่ใช้สำหรับตกแต่งรูปแบบการแสดงผลของหน้าเว็บที่สร้างด้วย HTML ให้มีความสวยงาม เป็นระเบียบ และทันสมัย เช่น การกำหนดสีตัวอักษร สีพื้นหลัง ขนาด ระยะห่าง และการจัดวางตำแหน่ง (Layout) ในโครงงานนี้ CSS ถูกใช้เพื่อตกแต่งความสวยงามของแอปพลิเคชัน โดยเฉพาะอย่างยิ่งการออกแบบในรูปแบบ Responsive Web Design ในโทนสีเขียวประจำมหาวิทยาลัยเกษตรศาสตร์ เพื่อรองรับการแสดงผลบนหน้าจอทั้งคอมพิวเตอร์ แท็บเล็ต และสมาร์ทโฟน
2.3.3 JavaScript [11]
JavaScript คือภาษาโปรแกรมสำหรับพัฒนาเว็บเพจให้มีการทำงานแบบโต้ตอบ (Interactive) สามารถตอบสนองการกระทำของผู้ใช้งานได้ทันทีโดยไม่ต้องโหลดหน้าเว็บใหม่ ในโครงงานนี้ JavaScript ถูกใช้เป็นกลไกหลักในการควบคุมลอจิก (Logic) ของหน้าบ้านแอปพลิเคชัน (Front-end) เช่น การสลับมุมมอง Single Page Application (SPA), การคำนวณระยะห่างพิกัด GPS, การตรวจจับและถอดรหัส QR Code, และการเชื่อมต่อข้อมูลกับคลาวด์แบบ Asynchronous
2.3.4 Supabase [12]
Supabase คือแพลตฟอร์มฐานข้อมูลบนคลาวด์แบบโอเพนซอร์ส (Backend-as-a-Service) ที่ขับเคลื่อนด้วยระบบจัดการฐานข้อมูลเชิงสัมพันธ์ PostgreSQL มีระบบรักษาความปลอดภัยระดับแถว (Row Level Security: RLS) และการรับส่งข้อมูลผ่าน RESTful API ในโครงงานนี้ Supabase ถูกใช้เป็นฐานข้อมูลหลักในการจัดเก็บข้อมูลผู้ใช้งาน ข้อมูลนิสิต ประวัติการส่งเอกสาร บันทึกเวลาการนิเทศงาน และพิกัดสถานประกอบการ
2.3.5 ไลบรารี jsQR [13]
jsQR คือไลบรารีภาษา JavaScript สำหรับการตรวจจับและถอดรหัส QR Code จากภาพวิดีโอสดได้อย่างแม่นยำและรวดเร็ว โดยประมวลผลบนเครื่องของผู้ใช้งานโดยตรงโดยไม่ต้องส่งภาพไปยังเซิร์ฟเวอร์ภายนอก ในโครงงานนี้ jsQR ถูกนำมาใช้เป็นเครื่องมือหลักในโมดูล Live Camera Scanner เพื่อให้อาจารย์นิเทศสามารถเปิดกล้องสมาร์ทโฟนสแกนบัตร Dynamic QR Code ของนิสิตเพื่อทำการเช็คอินลงพื้นที่
2.3.6 ไลบรารี SheetJS [14]
SheetJS (xlsx) คือไลบรารี JavaScript สำหรับการประมวลผล อ่าน และเขียนไฟล์สเปรดชีต (Spreadsheet) เช่น Microsoft Excel (.xlsx) และ CSV บนเว็บเบราว์เซอร์ได้อย่างมีประสิทธิภาพ ในโครงงานนี้ SheetJS ถูกนำมาใช้ในระบบของผู้ดูแลระบบสำหรับการนำเข้าข้อมูลรายชื่อนิสิตจำนวนมาก พร้อมแสดงผลตารางพรีวิวข้อมูลแบบเต็มจอ 100% ก่อนบันทึก และใช้สำหรับการประมวลผลส่งออกรายงานสรุปผลการนิเทศงาน
2.3.7 Visual Studio Code [15]
Visual Studio Code (VS Code) คือโปรแกรมแก้ไขซอร์สโค้ด (Source Code Editor) ระดับมืออาชีพที่พัฒนาโดยบริษัท Microsoft ซึ่งมีจุดเด่นด้านความเร็ว การจัดการไฟล์ที่มีประสิทธิภาพ และมีเครื่องมือสนับสนุนการเขียนโค้ดที่หลากหลาย ในโครงงานนี้ VS Code ถูกใช้เป็นสภาพแวดล้อมหลักในการพัฒนาและเขียนโปรแกรม ตลอดจนการทดสอบระบบเว็บแอปพลิเคชัน

การออกแบบระบบยึดหลักการออกแบบที่เน้นผู้ใช้งานเป็นศูนย์กลาง โดยจำแนกตามลำดับขั้นตอนกระบวนการทำงานจริงของแต่ละกลุ่มผู้ใช้งาน เพื่อให้เห็นความเชื่อมโยงของแต่ละฟังก์ชันและการแลกเปลี่ยนข้อมูลระหว่างผู้ใช้งานกับระบบฐานข้อมูลอย่างมีประสิทธิภาพ ดังนี้:
3.1.1 ขั้นตอนการทำงานของนิสิตสหกิจศึกษา 
ขั้นตอนการทำงานของนิสิตสหกิจศึกษาเริ่มต้นตั้งแต่การเข้าสู่ระบบเพื่อยืนยันตัวตนสองขั้นตอน การเปลี่ยนรหัสผ่านส่วนบุคคล การดาวน์โหลดแบบฟอร์มเปล่า การจัดเตรียมและอัปโหลดเอกสารรายงาน การติดตามผลการตรวจรับ ตลอดจนการเปิดแสดงบัตรประจำตัวดิจิทัลเพื่อรับการตรวจนิเทศงาน ดังแสดงในภาพที่ 4
  

ภาพที่ 4 Workflow ขั้นตอนการทำงานของนิสิตสหกิจศึกษา
________________


จากภาพที่ 4 สามารถอธิบายขั้นตอนการทำงานของนิสิตสหกิจศึกษาได้ดังต่อไปนี้:
1. นิสิตเปิดเข้าสู่เว็บแอปพลิเคชันการบันทึกและติดตามงานนิเทศสหกิจศึกษา ผ่านเว็บเบราว์เซอร์บนเครื่องคอมพิวเตอร์หรือสมาร์ตโฟน
2. นิสิตกรอกบัญชีผู้ใช้งานด้วยอีเมลมหาวิทยาลัยเกษตรศาสตร์ (@ku.th) และรหัสผ่านเพื่อเข้าสู่ระบบ
3. ระบบทำการตรวจสอบความถูกต้องของบัญชี และจัดส่งรหัสผ่านชั่วคราว OTP 8 หลัก ไปยังกล่องข้อความอีเมลมหาวิทยาลัยเพื่อยืนยันตัวตนสองขั้นตอน (Two-Factor Authentication: 2FA)
4. กรณีเป็นการเข้าสู่ระบบครั้งแรก ระบบจะบังคับให้นิสิตเปลี่ยนรหัสผ่านส่วนบุคคลใหม่ทันทีตามเกณฑ์ความปลอดภัย 4 ข้อ ได้แก่ ความยาวไม่น้อยกว่า 8 ตัวอักษร, ประกอบด้วยตัวพิมพ์ใหญ่, ตัวพิมพ์เล็ก, ตัวเลข และอักขระพิเศษ
5. นิสิตเข้าสู่หน้าหลัก แดชบอร์ดภาพรวมของนิสิต (Student Dashboard) ซึ่งแสดงข้อมูลสำคัญ ได้แก่
5.1 ข้อมูลส่วนตัว รหัสนิสิต สาขาวิชา อาจารย์นิเทศที่ปรึกษา และสถานที่ฝึกงาน
5.2 แถบแสดงสถานะความก้าวหน้าและการส่งเอกสารสหกิจศึกษาแบบฟอร์ม 
5.3 ปฏิทินแสดงกำหนดการและเวลานัดหมายการออกตรวจนิเทศของอาจารย์
6. นิสิตดาวน์โหลดแบบฟอร์มเปล่าสหกิจศึกษาได้แก่ FORM-00 ถึง FORM-11 ในรูปแบบไฟล์ PDF และ Microsoft Word เพื่อนำไปจัดเตรียมข้อมูลและประสานงานกับสถานประกอบการ
7. นิสิตดำเนินการกรอกข้อมูลในเอกสารและอัปโหลดไฟล์รายงานเข้าสู่ระบบ ตลอดจนส่งมอบงานตามภาระงาน ที่อาจารย์นิเทศมอบหมายตามกำหนดเวลา
8. นิสิตติดตามผลการตรวจรับเอกสารแบบเรียลไทม์ โดยสามารถตรวจสอบสถานะการอนุมัติ (อนุมัติผ่าน หรือ ตีกลับแก้ไข) พร้อมอ่านข้อคิดเห็น จากอาจารย์เพื่อนำไปปรับปรุงแก้ไข
9. นิสิตบันทึกและตั้งค่าตำแหน่งพิกัดทางภูมิศาสตร์ ของสถานประกอบการที่ตนเองปฏิบัติงานจริง ( เพื่อบันทึกพิกัดจริงลงในฐานข้อมูล
10. เมื่ออาจารย์นิเทศเดินทางมาถึงสถานประกอบการ นิสิตเปิดแสดงบัตรประจำตัว Dynamic QR Code ประจำตัวผ่านหน้าจอสมาร์ตโฟน ให้อาจารย์สแกนเพื่อตรวจสอบพิกัด และบันทึกผลการนิเทศสำเร็จ
________________


3.1.2 ขั้นตอนการทำงานของอาจารย์นิเทศ
ขั้นตอนการทำงานของอาจารย์นิเทศครอบคลุมตั้งแต่การเลือกห้องเรียนประจำกลุ่ม การตรวจรับเอกสารและให้ข้อเสนอแนะสะท้อนกลับ การมอบหมายภาระงาน การนัดหมายลงปฏิทินกลาง จนถึงการลงพื้นที่ตรวจนิเทศจริงโดยใช้กล้องสดสแกน QR Code ตรวจสอบพิกัด Geofencing และการประเมินคะแนนนิเทศงาน ดังแสดงในภาพที่ 5
  

ภาพที่ 5 Workflow ขั้นตอนการทำงานของอาจารย์นิเทศ
________________


จากภาพที่ 5 สามารถอธิบายขั้นตอนการทำงานของอาจารย์นิเทศได้ดังต่อไปนี้:
1. อาจารย์นิเทศเข้าสู่ระบบเว็บแอปพลิเคชันด้วยบัญชีอีเมลมหาวิทยาลัย (@ku.th) และยืนยันความปลอดภัยด้วยรหัส OTP 8 หลัก
2. อาจารย์เลือกห้องเรียนและหมู่เรียนที่รับผิดชอบเพื่อเข้าถึงข้อมูลนิสิตในกลุ่มที่ตนเองดูแล
3. ตรวจสอบรายชื่อนิสิตในกลุ่ม ข้อมูลสถานประกอบการ เบอร์โทรติดต่อพี่เลี้ยง และรายละเอียดหัวข้อโครงงานสหกิจศึกษา
4. เข้าสู่หน้าตารางแมทริกซ์สถานะเอกสาร เพื่อตรวจสอบภาพรวมการส่งเอกสารของนิสิตทุกคนในคราวเดียวแบบเรียลไทม์
5. เปิดตรวจเอกสารรายงานสหกิจศึกษารายฉบับ โดยเลือกผลการประเมิน ได้แก่ อนุมัติรับรองเอกสาร หรือปฏิเสธตีกลับแก้ไขพร้อมระบุข้อคิดเห็น ให้นิสิตนำไปปรับปรุง
6. จัดการระบบภาระงาน โดยกำหนดหัวข้อ คำชี้แจง วันกำหนดส่งงาน และตรวจสอบรายชื่อนิสิตที่ส่งงานแล้วหรือยังไม่ส่งงาน
7. วางแผนการเดินทางและบันทึกกำหนดการนัดหมายการออกตรวจนิเทศงานลงบนปฏิทินกลางของระบบ เพื่อให้นิสิตและผู้เกี่ยวข้องรับทราบล่วงหน้า
8. เมื่ออาจารย์เดินทางถึงสถานที่ฝึกงาน เปิดเมนูสแกนเนอร์กล้องสด บนสมาร์ตโฟน แล้วสแกนบัตร QR Code ของนิสิต
9. ระบบทำการถอดรหัสข้อมูล ดึงพิกัด Geolocation ปัจจุบัน และคำนวณระยะห่างหากอยู่ภายในรัศมีไม่เกิน 500 เมตร ระบบจะทำการเช็คอินสำเร็จและแสดงการ์ดสีเขียวรับรองการลงพื้นที่จริง
10. อาจารย์อัปโหลดภาพถ่ายหลักฐานการนิเทศสองชั้น (รูปถ่ายคู่กับนิสิตและพนักงานพี่เลี้ยง) กรอกแบบฟอร์มประเมินคะแนนตามเกณฑ์รูบริก 6 ด้าน และบันทึกผลการนิเทศเสร็จสิ้นสมบูรณ์
________________


3.1.3 ขั้นตอนการทำงานของผู้ดูแลระบบ (Admin Workflow)
ขั้นตอนการทำงานของผู้ดูแลระบบครอบคลุมการกำกับดูแลภาพรวม การนำเข้าข้อมูลนิสิตและสถานประกอบการผ่านไฟล์ Excel การตรวจสอบความถูกต้องของข้อมูลผ่านตารางพรีวิว การบริหารจัดการสิทธิ์บัญชีผู้ใช้ และการประมวลผลส่งออกรายงานสรุปผลการนิเทศ ดังแสดงในภาพที่ 6
  

ภาพที่ 6 Workflow ขั้นตอนการทำงานของผู้ดูแลระบบ
________________


จากภาพที่ 6 สามารถอธิบายขั้นตอนการทำงานของผู้ดูแลระบบได้ดังต่อไปนี้:
1. ผู้ดูแลระบบ (Administrator) เข้าสู่ระบบแดชบอร์ดส่วนกลางด้วยบัญชีผู้ดูแลระบบ เพื่อบริหารจัดการโครงสร้างและข้อมูลของระบบทั้งหมด
2. ตรวจสอบแดชบอร์ดสถิติภาพรวม (Admin Dashboard) แสดงสรุปจำนวนนิสิตทั้งหมด จำนวนอาจารย์นิเทศ สถานประกอบการ อัตราการส่งเอกสาร และสถิติการนิเทศที่สำเร็จแล้ว
3. นำเข้าข้อมูลเริ่มต้นของภาคการศึกษาผ่านการอัปโหลดไฟล์ Excel (.xlsx) หรือ CSV ซึ่งประกอบด้วยข้อมูลนิสิต อาจารย์นิเทศ และข้อมูลสถานที่ฝึกงาน
4. ระบบแสดงผลข้อมูลผ่านตารางพรีวิวขนาดใหญ่เต็มหน้าจอ (Data Preview Modal 100%) แสดงข้อมูล 7 คอลัมน์หลัก เพื่อให้ตรวจสอบความถูกต้องและความสมบูรณ์ของข้อมูลก่อนบันทึก
5. ผู้ดูแลระบบกดยืนยันการนำเข้า ระบบจะดำเนินการบันทึกและจัดเก็บข้อมูลลงสู่ฐานข้อมูล Supabase Cloud Database แบบ Batch Insertion พร้อมแสดงป๊อปอัปแจ้งผลสัมฤทธิ์
6. ผู้ดูแลระบบสามารถใช้ตัวกรองข้อมูล (Filter) ตามปีการศึกษา ภาคการศึกษา และค้นหารายชื่อนิสิตแบบเรียลไทม์เพื่อตรวจสอบหรือแก้ไขข้อมูลรายบุคคล
7. ตรวจสอบและปรับปรุงตำแหน่งพิกัดทางภูมิศาสตร์ (GPS Latitude/Longitude) ของสถานประกอบการบนแผนที่ เพื่อให้การคำนวณ Geofencing 500 เมตรของอาจารย์นิเทศมีความแม่นยำสูงสุด
8. บริหารจัดการบัญชีผู้ใช้งาน กำหนดสิทธิ์การเข้าถึง (Role-Based Access Control) ตลอดจนการปลดล็อกบัญชีหรือรีเซ็ตรหัสผ่านให้แก่นิสิตและอาจารย์ในกรณีที่เกิดปัญหา
9. ติดตามและตรวจสอบสถานะการออกตรวจนิเทศของอาจารย์แต่ละท่าน ตรวจสอบหลักฐานภาพถ่ายและคะแนนประเมินที่ถูกส่งเข้าสู่ระบบ
10. ประมวลผลและส่งออกรายงานสรุปผลการนิเทศงานของภาควิชาทั้งหมด ในรูปแบบไฟล์ Microsoft Excel (.xlsx) และเอกสารสรุป PDF เพื่อใช้เป็นหลักฐานและนำเสนอต่อคณะวิทยาศาสตร์ต่อไป
________________


3.1.4 ขั้นตอนการสแกนและตรวจสอบพิกัด Geofencing 500 เมตร
เมื่ออาจารย์กดปุ่มสแกน QR Code ระบบจะทำงานตามลำดับดังนี้: 1) เปิดกล้องสดและประมวลผลถอดรหัสนิสิตผ่าน jsQR 2) ดึงพิกัดปัจจุบันของอาจารย์ผ่าน W3C Geolocation API 3) ดึงพิกัดสถานประกอบการของนิสิตจากฐานข้อมูล 4) คำนวณระยะห่างด้วย Haversine Formula 5) หากระยะห่าง ≤ 500 เมตร ระบบบันทึกการเช็คอินสำเร็จและเปลี่ยนสถานะนิสิตเป็น 'นิเทศแล้ว' 6) หากระยะห่าง > 500 เมตร ระบบแสดงการแจ้งเตือนสีแดงและปฏิเสธการเช็คอินทันที

4.1 ขอบเขตการทำงานและสิทธิ์การใช้งานของแต่ละบทบาท
เว็บแอปพลิเคชันการบันทึกและติดตามงานนิเทศสหกิจศึกษา ได้รับการพัฒนาขึ้นโดยแบ่งสิทธิ์และหน้าที่การทำงานออกเป็น 3 บทบาทหลักอย่างชัดเจน ดังนี้:
1. นิสิตสหกิจศึกษา (Student): สามารถเข้าสู่ระบบด้วยอีเมลมหาวิทยาลัยและ OTP, แสดงบัตร Dynamic QR Code สำหรับการเช็คอิน, ดาวน์โหลดแบบฟอร์มเปล่า FORM-00 ถึง FORM-11, อัปโหลดเอกสารรายงาน, ตรวจสอบสถานะการตรวจรับและข้อคิดเห็นสะท้อนกลับแบบรายฉบับ, ตรวจสอบปฏิทินนัดหมาย และกำหนดพิกัดสถานที่ฝึกงานของตนเอง
2. อาจารย์นิเทศ (Advisor): สามารถเลือกดูห้องเรียนแยกหมู่, ตรวจรับเอกสารพร้อมระบุข้อคิดเห็นรายฉบับ, สั่งงานและมอบหมายงาน, สร้างนัดหมายบนปฏิทินกลาง, เปิดกล้องสดสแกน QR Code เช็คอินพิกัด GPS รัศมี 500 เมตร, อัปโหลดภาพถ่ายหลักฐานการนิเทศ และบันทึกคะแนนประเมินผล
3. ผู้ดูแลระบบ (Admin): สามารถติดตามสถิตินิเทศงานแบบเรียลไทม์, นำเข้าไฟล์ Excel รายชื่อนิสิตพร้อมตารางพรีวิวก่อนนำเข้า, กรองข้อมูลตามภาคการศึกษา, ค้นหาข้อมูลนิสิตแบบทันที, กำหนดพิกัดสถานประกอบการ และส่งออกรายงานสรุปในรูปแบบ Excel และ PDF
4.2 การทำงานจริงของระบบและส่วนต่อประสานผู้ใช้งาน (User Interface Design & System Walkthrough)
ในหัวข้อนี้แสดงผลการทำงานจริงของระบบผ่านภาพจับหน้าจอ (Screen Captures) ครบถ้วนทั้ง 37 ขั้นตอนการทำงาน โดยไม่มีการใช้ภาพซ้ำ พร้อมคำอธิบายการทำงานในแต่ละขั้นตอน ดังนี้:
กลุ่มที่ 1: ระบบยืนยันตัวตนและความปลอดภัย (ขั้นตอนที่ 1 ถึง 6)
ขั้นตอนที่ 1: หน้าจอเข้าสู่ระบบเริ่มต้น ผู้ใช้งานสามารถเข้าสู่ระบบผ่านหน้าเว็บหลัก โดยรองรับการเข้าใช้งานด้วยอีเมลมหาวิทยาลัย (@ku.th) พร้อมมีตัวเลือกสลับบทบาทสำหรับการทดสอบระบบอย่างปลอดภัย
  

ภาพที่ 7 หน้าจอเข้าสู่ระบบเริ่มต้น
ขั้นตอนที่ 2: การกรอกข้อมูลบัญชีผู้ใช้งาน ผู้ใช้งานกรอกอีเมลมหาวิทยาลัย (@ku.th) และรหัสผ่านที่กำหนดไว้ในระบบ โดยมีระบบตรวจสอบความถูกต้องของรูปแบบอีเมลก่อนส่งข้อมูล
  

ภาพที่ 8 การกรอกข้อมูลบัญชีผู้ใช้งานอีเมลมหาวิทยาลัยและรหัสผ่าน
ขั้นตอนที่ 3: ปุ่มเปิด-ปิดการแสดงผลรหัสผ่าน ผู้ใช้งานสามารถคลิกไอคอนรูปดวงตาด้านขวาของช่องรหัสผ่าน เพื่อสลับระหว่างการซ่อนรหัสผ่านเป็นจุดวงกลม หรือการเปิดแสดงตัวอักษรจริงเพื่อตรวจสอบความถูกต้องก่อนกดเข้าสู่ระบบ
  

ภาพที่ 9 การเปิด-ปิดการแสดงผลรหัสผ่านเพื่อตรวจสอบความถูกต้อง
ขั้นตอนที่ 4: การจัดส่งรหัสยืนยันตัวตน OTP 8 หลัก ไปยังกล่องข้อความอีเมลมหาวิทยาลัย เมื่อผู้ใช้งานกรอกรหัสผ่านถูกต้อง ระบบความปลอดภัยจะสุ่มสร้างรหัส One-Time Password (OTP) ความยาว 8 หลัก และจัดส่งตรงไปยังกล่องจดหมายอีเมลของนิสิตทันที เพื่อใช้ยืนยันตัวตนสองชั้น (Two-Factor Authentication: 2FA) โดยในอีเมลระบุรหัส OTP 8 หลัก คือ '64672086' พร้อมแจ้งเตือนระยะเวลาหมดอายุภายใน 5 นาที
  

ภาพที่ 10 รหัสยืนยันตัวตน OTP 8 หลัก ที่ระบบจัดส่งไปยังกล่องข้อความอีเมลมหาวิทยาลัย
ขั้นตอนที่ 5: หน้าต่างยืนยันตัวตนและกรอกรหัส OTP 8 หลัก เข้าสู่ระบบ ผู้ใช้งานนำรหัส OTP 8 หลัก ที่ได้รับจากอีเมล (รหัส 64672086) มากรอกลงในหน้าต่างป๊อปอัปยืนยันตัวตนบนระบบ โดยตัวเลข OTP 8 หลักที่กรอกตรงกับรหัสที่ระบุในอีเมลทุกประการ เพื่อตรวจสอบความถูกต้องของเซสชันก่อนได้รับอนุญาตให้เข้าสู่ระบบงานสหกิจศึกษา
  

ภาพที่ 11 หน้าต่างยืนยันตัวตนและกรอกรหัส OTP 8 หลัก เข้าสู่ระบบ
ขั้นตอนที่ 6: หน้าต่างบังคับเปลี่ยนรหัสผ่านครั้งแรก ในกรณีที่ผู้ใช้งานเข้าสู่ระบบเป็นครั้งแรก ระบบจะบังคับให้เปลี่ยนรหัสผ่านส่วนบุคคลใหม่ทันทีตามเกณฑ์ความปลอดภัย 4 ข้อ ได้แก่ ความยาวไม่น้อยกว่า 8 ตัวอักษร, ประกอบด้วยตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก, ตัวเลข และอักขระพิเศษ
  

ภาพที่ 12 หน้าต่างบังคับเปลี่ยนรหัสผ่านครั้งแรกตามเกณฑ์ความปลอดภัย
กลุ่มที่ 2: ระบบสำหรับนิสิตสหกิจศึกษา (ขั้นตอนที่ 7 ถึง 13)
ขั้นตอนที่ 7: หน้าแดชบอร์ดภาพรวมของนิสิตสหกิจศึกษา แสดงแถบสถานะความก้าวหน้าการฝึกงาน สถานะการออกนิเทศงานของอาจารย์ สถิติการส่งเอกสารแบบฟอร์ม และรายการนัดหมายที่กำลังจะมาถึง
  

ภาพที่ 13 แดชบอร์ดภาพรวมของนิสิตสหกิจศึกษา
ขั้นตอนที่ 8: บัตรประจำตัว Dynamic QR Code นิสิตสามารถเปิดแสดงบัตรคิวอาร์โค้ดประจำตัวผ่านหน้าจอมือถือ ซึ่งสร้างขึ้นแบบไดนามิกตามรหัสนิสิตและเซสชัน เพื่อให้อาจารย์นิเทศใช้กล้องสมาร์ทโฟนสแกนเช็คอินเมื่อเดินทางมาถึงสถานประกอบการ
  

ภาพที่ 14 QR Code ของนิสิตสหกิจศึกษา
ขั้นตอนที่ 9: คลังแบบฟอร์มเปล่าสหกิจศึกษา นิสิตสามารถเข้าถึงคลังแบบฟอร์มทางการของคณะวิทยาศาสตร์ (FORM-00 ถึง FORM-11) โดยสามารถกดพรีวิวดูเนื้อหาแบบฟอร์ม และกดดาวน์โหลดไฟล์เอกสารเพื่อนำไปกรอกข้อมูลได้อย่างสะดวก
  

ภาพที่ 15 คลังแบบฟอร์มเปล่าสหกิจศึกษา 
ขั้นตอนที่ 10: ฟอร์มอัปโหลดเอกสารสหกิจศึกษา นิสิตสามารถเลือกแบบฟอร์มที่ต้องการส่ง แนบไฟล์เอกสาร (PDF หรือ Word) พร้อมระบุข้อความอธิบายเพิ่มเติมเข้าสู่ระบบคลาวด์
  

ภาพที่ 16 หน้าต่างอัปโหลดเอกสารสหกิจศึกษา
ขั้นตอนที่ 11: ประวัติการส่งเอกสารและผลการตรวจรับรายฉบับ นิสิตสามารถตรวจสอบประวัติการส่งเอกสารทั้งหมด พร้อมดูผลการอนุมัติ (✓ อนุมัติ หรือ ✕ ตีกลับแก้ไข) และข้อคิดเห็นสะท้อนกลับจากอาจารย์นิเทศแบบเจาะจงรายฉบับ 
  

ภาพที่ 17 ประวัติการส่งเอกสารและผลการตรวจรับ/ข้อคิดเห็นสะท้อนกลับรายฉบับ
ขั้นตอนที่ 12: ปฏิทินกำหนดการและนัดหมาย นิสิตสามารถดูวันเวลาที่อาจารย์ที่ปรึกษาจะลงพื้นที่ตรวจนิเทศ ณ สถานประกอบการล่วงหน้า เพื่อเตรียมความพร้อมในการประสานงานกับพนักงานพี่เลี้ยง
  

ภาพที่ 18 ปฏิทินกำหนดการและนัดหมายการออกตรวจนิเทศของนิสิต
ขั้นตอนที่ 13: ระบบติดตามความก้าวหน้าโครงงาน นิสิตสามารถบันทึกหัวข้อโครงงานสหกิจ วัตถุประสงค์ และอัปเดตเปอร์เซ็นต์ความคืบหน้าของงานเพื่อให้อาจารย์ที่ปรึกษาติดตามได้อย่างต่อเนื่อง
  

ภาพที่ 19 ระบบบันทึกและติดตามความก้าวหน้าโครงงาน 
กลุ่มที่ 3: ระบบสำหรับอาจารย์นิเทศ (ขั้นตอนที่ 14 ถึง 30)
ขั้นตอนที่ 14: หน้าเลือกห้องเรียนของอาจารย์นิเทศ อาจารย์สามารถเลือกสลับดูข้อมูลนิสิตตามหมู่เรียนจริง 
  

ภาพที่ 20 การเลือกห้องเรียนของอาจารย์นิเทศ
ขั้นตอนที่ 15: หน้ารายชื่อนิสิตในห้องเรียน แสดงการ์ดข้อมูลนิสิตทุกคนในความดูแล ระบุชื่อ สถานประกอบการ เบอร์ติดต่อ และสถานะการตรวจนิเทศ
  

ภาพที่ 21 หน้ารายชื่อนิสิตในห้องเรียนและข้อมูลสถานที่ฝึกงาน
ขั้นตอนที่ 16: หน้าต่างรายละเอียดนิสิต แสดงข้อมูลพี่เลี้ยง แผนที่ตั้งสถานประกอบการ และพิกัดละติจูด/ลองจิจูดอ้างอิง
  

ภาพที่ 22 รายละเอียดนิสิต ข้อมูลพี่เลี้ยง และพิกัดสถานที่ฝึกงาน
ขั้นตอนที่ 17: ตารางแมทริกซ์สรุปสถานะการส่งเอกสาร แสดงภาพรวมสถานะการส่งเอกสารแบบฟอร์ม ของนิสิตทุกคนในห้องเรียน ช่วยให้อาจารย์ติดตามเอกสารที่ค้างส่งได้อย่างรวดเร็ว
  

ภาพที่ 23 ตารางแมทริกซ์สรุปสถานะการส่งเอกสารของนิสิตทุกคน
ขั้นตอนที่ 18: หน้าต่างตรวจรับเอกสารรายฉบับ อาจารย์สามารถเปิดดูไฟล์เอกสารของนิสิต และกดปุ่มอนุมัติเอกสารพร้อมบันทึกคะแนนหรือคำชม
  

ภาพที่ 24 หน้าต่างตรวจรับเอกสารรายฉบับและผลการอนุมัติ
ขั้นตอนที่ 19: การปฏิเสธเอกสารพร้อมระบุข้อคิดเห็นตีกลับ อาจารย์สามารถกดปุ่มปฏิเสธเอกสารและพิมพ์ข้อคิดเห็นระบุจุดที่ต้องแก้ไขอย่างละเอียด เพื่อให้นิสิตนำไปปรับปรุงและส่งใหม่
  

ภาพที่ 25 การปฏิเสธเอกสารพร้อมระบุข้อคิดเห็นตีกลับแก้ไข
ขั้นตอนที่ 20: ระบบจัดการภาระงาน (Assignments) อาจารย์สามารถบริหารจัดการภาระงานที่มอบหมายแก่นิสิต ทั้งงานค้นคว้า รายงานความก้าวหน้า และแบบฝึกหัด
  

ภาพที่ 26 ระบบจัดการภาระงานและการมอบหมายงาน

ภาพที่ 30 หน้าจอกล้องสดสำหรับสแกน QR Code

ภาพที่ 37 แดชบอร์ดสรุปสถิตินิสิตและสถานะการนิเทศของผู้ดูแลระบบ

5.1 สรุปผลการดำเนินงาน
โครงงานการพัฒนาเว็บแอปพลิเคชันการบันทึกและติดตามงานนิเทศสหกิจศึกษา ได้ดำเนินการวิเคราะห์ ออกแบบ และพัฒนาระบบจนเสร็จสมบูรณ์ตามขอบเขตงานที่กำหนดไว้ โดยผ่านการทดสอบฟังก์ชันการทำงานจริงครบถ้วนทั้ง 37 ขั้นตอนการทำงาน ซึ่งผลการดำเนินงานสามารถสรุปเปรียบเทียบตามวัตถุประสงค์ของโครงงานได้ดังนี้:
1. ผลการพัฒนาระบบเว็บแอปพลิเคชัน 3 บทบาท : คณะผู้พัฒนาได้พัฒนาระบบที่สมบูรณ์แบบ รองรับการทำงานทั้งบนคอมพิวเตอร์และสมาร์ทโฟน ครอบคลุมฟังก์ชันการทำงานของ 3 บทบาทหลัก ได้แก่ นิสิตสหกิจศึกษา อาจารย์นิเทศ และผู้ดูแลระบบ พร้อมระบบความปลอดภัยยืนยันตัวตนสองชั้นด้วยรหัส OTP 8 หลัก ผ่านอีเมลมหาวิทยาลัย และระบบ Auth Guard ป้องกันการเข้าถึงข้ามสิทธิ์
2. ผลการพัฒนากลไกตรวจสอบพิกัดลงพื้นที่จริง 500 เมตร: การบูรณาการ Live Camera QR Code Scanner ร่วมกับ W3C Geolocation API และสูตรคำนวณระยะทางทำให้ระบบสามารถจำกัดรัศมีตรวจนิเทศไม่เกิน 500 เมตรได้อย่างแม่นยำ ป้องกันการเช็คอินนอกสถานที่จริงและสร้างหลักฐานเชิงประจักษ์ที่มีความโปร่งใสและตรวจสอบได้
3. ผลการพัฒนาระบบคลังเอกสารแบบฟอร์มและภาพถ่ายหลักฐาน : การพัฒนาระบบคลังแบบฟอร์ม พร้อมระบบตรวจรับและสะท้อนกลับข้อคิดเห็นรายฉบับ และคลังภาพถ่ายหลักฐานการนิเทศสองชั้น ช่วยลดการใช้กระดาษ แก้ปัญหาเอกสารสูญหาย และนิสิตได้รับข้อคิดเห็นในการปรับปรุงตนเองได้อย่างทันท่วงที
4. ผลการพัฒนาระบบจัดการข้อมูลนิสิตและออกรายงานสรุป : ตารางพรีวิวไฟล์ Excel ขนาดใหญ่เต็มจอ 100% ทั้งก่อนและหลังนำเข้า ช่วยให้ผู้ดูแลระบบสามารถตรวจสอบความถูกต้องของข้อมูลนิสิตจำนวนมากได้อย่างรวดเร็วและแม่นยำ พร้อมทั้งสามารถประมวลผลส่งออกรายงานสรุปผลการนิเทศในรูปแบบ Excel Spreadsheet (.xlsx) และ PDF (.pdf) ได้ทันที
5.2 ปัญหาและอุปสรรคที่พบระหว่างการพัฒนา
ในระหว่างกระบวนการพัฒนาระบบ คณะผู้พัฒนาได้พบปัญหาและอุปสรรคทางเทคนิคที่เกิดขึ้นจริงจากการพัฒนาซอฟต์แวร์และการเชื่อมต่อระบบ โดยมีรายละเอียดและแนวทางแก้ไขดังนี้:
1. ปัญหาการรักษาความปลอดภัยและการควบคุมการเข้าถึงข้ามบทบาท (Authentication Guard บนสถาปัตยกรรม SPA): เนื่องจากระบบพัฒนาด้วยสถาปัตยกรรม Pure Vanilla JavaScript Single Page Application โดยไม่มีเฟรมเวิร์กช่วยจัดการ Routing ในช่วงเริ่มต้นของการพัฒนาจึงพบปัญหาว่า ผู้ใช้งานสามารถพิมพ์ URL Parameter ข้ามขั้นตอนการยืนยันตัวตนได้โดยตรง เช่น การพิมพ์ dashboard.html?user=admin หรือ ?user=advisor ส่งผลให้ข้ามหน้าเข้าสู่ระบบและระบบ OTP ไปได้ คณะผู้พัฒนาจึงได้แก้ไขโดยการพัฒนาระบบ Auth Guard ตรวจสอบสถานะการยืนยันตัวตนระดับ Client-side ทันทีที่โหลดหน้าจอ หากไม่มี Session Token ที่ถูกต้อง หรือยังไม่ผ่านการยืนยัน OTP 8 หลัก ระบบจะล้างค่าเซสชันและบังคับรีไดเรกต์กลับสู่หน้า index.html ทันที
2. ปัญหาข้อจำกัดด้านความปลอดภัยของเว็บเบราว์เซอร์ในการเข้าถึงฮาร์ดแวร์ (Secure Context): ในการพัฒนาโมดูลกล้องสดสแกน QR Code (Live Camera Scanner) และโมดูลดึงพิกัดทางภูมิศาสตร์ (W3C Geolocation API) พบปัญหาว่าเว็บเบราว์เซอร์สมัยใหม่ (ทั้ง Google Chrome และ Safari) มีนโยบายความปลอดภัยที่ไม่อนุญาตให้สคริปต์เข้าถึงกล้องและเซนเซอร์พิกัด GPS หากหน้าเว็บไม่ได้ทำงานภายใต้ Secure Context (HTTPS หรือ localhost) ส่งผลให้เมื่อทดสอบระบบผ่าน IP Address ในเครือข่ายแลน เบราว์เซอร์จะบล็อกการเปิดกล้องและไม่ส่งค่าพิกัด คณะผู้พัฒนาจึงแก้ไขโดยการทดสอบผ่าน localhost และพัฒนาสคริปต์เซิร์ฟเวอร์ควบคุมสภาพแวดล้อม (server.ps1) เพื่อให้การเรียกใช้ฮาร์ดแวร์ทำงานได้อย่างถูกต้อง
3. ปัญหาการจัดการพื้นที่แสดงผลตารางนำเข้าข้อมูลนิสิตผ่านไฟล์ Excel (Modal Layout Overflow): ในการนำเข้าข้อมูลนิสิตผ่านไฟล์ Excel/CSV พบว่าโครงสร้างข้อมูลมีหลายคอลัมน์ (รหัสนิสิต, ชื่อ-นามสกุล, หมู่เรียน, สถานประกอบการ, พิกัดละติจูดและลองจิจูด) ทำให้เมื่อนำข้อมูลมาแสดงผลในหน้าต่าง Pop-up Modal ขนาดมาตรฐาน เกิดปัญหาข้อความตกหล่น ตัวหนังสือซ้อนทับ และตารางล้นกรอบหน้าจอ ทำให้ตรวจสอบข้อมูลก่อนนำเข้าได้ยาก คณะผู้พัฒนาจึงได้ปรับปรุงสถาปัตยกรรม UI ใหม่เป็นแบบ Full-Width 100% กว้างเต็มหน้าจอ และแยกขั้นตอนเป็น Pre-Import Preview เพื่อตรวจเช็คความถูกต้องและกรองแถวข้อมูลที่ไม่สมบูรณ์ออกก่อน และ Post-Import Modal เพื่อแสดงสรุปผลการนำเข้าจริง
4. ปัญหาความไม่ต่อเนื่องในการซิงค์ข้อมูลระหว่างคลาวด์กับสภาวะออฟไลน์ (Dual-Tier Resilience): ในระหว่างการพัฒนาและทดสอบการเชื่อมต่อกับ Supabase Cloud Database พบว่าในบางช่วงเวลาที่สัญญาณเครือข่ายอินเทอร์เน็ตมีความล่าช้าหรือหลุดชั่วคราว การดึงข้อมูลแบบฟอร์มเอกสารหรือรายชื่อนิสิตอาจหยุดชะงัก คณะผู้พัฒนาจึงได้ออกแบบสถาปัตยกรรมจัดเก็บข้อมูลแบบสองชั้น (Dual-Tier Storage) ใน supabase-client.js โดยใช้ LocalStorage เป็นแคชสำรองข้อมูลอัตโนมัติ ทำให้ผู้ใช้ยังคงสามารถดูข้อมูลและปฏิบัติงานต่อได้แม้ไม่มีอินเทอร์เน็ต และระบบจะทำการเชื่อมโยงข้อมูลกับฐานข้อมูลคลาวด์ทันทีเมื่อสัญญาณกลับมาออนไลน์
5. ปัญหาความซับซ้อนในการจัดการสถานะการตรวจรับเอกสารสหกิจศึกษาแบบรายฉบับ (Granular Document Review): เดิมระบบออกแบบให้ตรวจรับการส่งเอกสารเป็นภาพรวมชุดเดียว แต่ในกระบวนการจริง นิสิตต้องส่งเอกสารหลายแบบฟอร์ม (FORM-00 ถึง FORM-11) ซึ่งแต่ละฉบับมีข้อผิดพลาดและผลการตรวจรับที่แตกต่างกัน (บางฉบับผ่าน แต่บางฉบับต้องตีกลับแก้ไข) คณะผู้พัฒนาจึงต้องปรับโครงสร้างฐานข้อมูลและหน้าต่างตรวจรับเอกสารให้อาจารย์สามารถคลิกอนุมัติหรือส่งตีกลับพร้อมพิมพ์ข้อคิดเห็นสะท้อนกลับ (Feedback Comment) แยกเจาะจงเป็นรายไฟล์ได้อย่างอิสระ
6. ปัญหาการส่งผ่านพิกัด GPS ของสถานประกอบการจากการนำเข้าไฟล์: ในการทดสอบคำนวณระยะห่างด้วยสูตร Haversine Formula พบปัญหาว่าข้อมูลสถานประกอบการของนิสิตบางส่วนยังไม่มีค่าพิกัดละติจูด/ลองจิจูดในระบบ ส่งผลให้ระบบเข้าใจว่าอยู่นอกรัศมีและปฏิเสธการเช็คอิน คณะผู้พัฒนาจึงได้ปรับปรุงระบบนำเข้าไฟล์ Excel ให้ดึงค่าพิกัดจากตารางเข้าสู่ฐานข้อมูลโดยตรง พร้อมทั้งเพิ่มหน้าต่างให้นิสิตและอาจารย์สามารถตรวจสอบและตั้งค่าพิกัด GPS สถานประกอบการของตนเองได้ (Student GPS Setting)
5.3 แนวทางการพัฒนาต่อยอดในอนาคต
1. การเชื่อมต่อกับระบบสารสนเทศกลางของมหาวิทยาลัย (KU All-Login): พัฒนาระบบยืนยันตัวตนให้เชื่อมโยงกับ Single Sign-On (SSO) ของมหาวิทยาลัยเกษตรศาสตร์โดยตรง เพื่อให้นิสิตและอาจารย์สามารถเข้าสู่ระบบด้วยบัญชีเคยูเดิมโดยไม่ต้องลงทะเบียนใหม่
2. ระบบแจ้งเตือนอัตโนมัติผ่าน LINE Notify / Push Notification: พัฒนาระบบส่งข้อความแจ้งเตือนเตือนความจำกำหนดส่งเอกสาร และแจ้งเตือนเมื่อมีการนัดหมายลงพื้นที่ผ่านแอปพลิเคชัน LINE เพื่อความสะดวกในการสื่อสารแบบเรียลไทม์
3. การขยายผลสู่ระดับมหาวิทยาลัย: พัฒนาสถาปัตยกรรมระบบให้รองรับการใช้งานของทุกภาควิชาและทุกคณะภายในมหาวิทยาลัยเกษตรศาสตร์ทั้ง 4 วิทยาเขต เพื่อสร้างมาตรฐานการนิเทศงานสหกิจศึกษาดิจิทัลที่เป็นเอกภาพในระดับสถาบัน
